## Список изменений v2.0.0 (Changelog)

Полный перечень всех новых протоколов, подсистем, оптимизаций ядра, улучшений безопасности и исправлений в **C-Tunnel v2.0.0** по сравнению с `v1.1.1` (подробный журнал в [CHANGELOG.md](CHANGELOG.md)):

- **21 новый транспорт (рост с 28 до 49 методов в 6 семействах) и 3 режима работы:**
  - **3 режима туннелей:** **Reverse** (зарубежный сервер подключается к Ирану; 0 исходящих подключений из Ирана), **Direct** (прямое подключение с минимальной задержкой) и **8× BBR Turbo Direct** (8 параллельных TCP-потоков с BBR).
  - **9 туннелей уровня L4 Direct и Reverse (`pkg/l4`):** `tcp` (пул из 16 соединений + ядерный `splice`), `tcpmux` (`smux` v2 поверх 4 TCP-соединений), `pck` (KCP внутри формируемых вручную TCP-сегментов через raw-сокет с BPF-фильтром и AES без TCP-состояния ядра), `ws` (WebSocket с поддержкой `Host`/SNI), `wsmux`, `wss` (WebSocket в TLS), `wssmux`, `udp` (пул KCP-сессий поверх UDP с явным сигналом FIN) и `udpmux`. Проброс TCP и UDP без туннельного IP и без TCP-in-TCP, настройка по ссылке `ctunnel://` или вручную, автоматический L4 Failover.
  - **4 выделенных игровых протокола (Direct и Reverse):** `game-udp` (минимальный пинг, `DSCP EF` / `SO_PRIORITY 6`, `IP_MTU_DISCOVER=DO`, без блокировки очереди), `game-fec` (**0-RTT XOR-FEC** восстановление потерь без ожидания повтора), `game-dup` (двойная отправка малых пакетов `<= 320 Б`) и `game-kcp` (проброс портов L4 на KCP с тиком `5 мс`).
  - **2 Stealth-транспорта уровня L3 (Direct и Reverse):** `faketcp` (TLS-записи внутри TCP-сегментов на носителе `pck` со скоростью UDP) и `icmp` (AES-256-GCM внутри ICMP Echo ping с подавлением собственных ответов ядра через iptables).
  - **3 новых метода маскировки UDP-Crypt (Direct и Reverse):** `stun-turn` (WebRTC TURN ChannelData, порт `3478`), `gtp-u` (3GPP GTP-U G-PDU мобильного ядра, порт `2152`) и `esp-udp` (IPsec NAT-T ESP-in-UDP, порт `4500`).
  - **3 новых высокоскоростных ядерных транспорта L3:** `bareudp` (IPv4 напрямую в UDP для Linux 5.7+ без лишнего заголовка, порт `6635`), `xgre` (многопоточный GRE с ключом, `ignore-df`, FOU, ECMP и поддержкой MikroTik) и `xgre-ip` (IPIP поверх многопоточного `xGRE`).
- **Оптимизации движка, ядра и сети (ускорение до 2.5×):**
  - **Переход на Go 1.26.10:** обновление с Go 1.22 до Go 1.26.10 и `golang.org/x/net v0.62.0` устранило все 37 уязвимостей стандартной библиотеки по `govulncheck` (0 достижимых CVE).
  - **Zero-Copy `splice` в ядре Linux для L4 TCP:** передача данных между сокетами напрямую в ядре без копирования в userspace.
  - **Пакетные ACK KCP раз в 10 мс и окно 4096 сегментов:** ускорение `udp`, `udpmux` и `pck` в **1.6–2.5 раза** между неймспейсами, на **~25%** при RTT `50 мс` и на **10–20%** при RTT `150 мс`.
  - **Окно `smux` 16 МиБ и фреймы 64 КиБ:** 4-кратное увеличение потокового окна (`4 МиБ → 16 МиБ`) для дальних каналов.
  - **Векторный пакетный ввод-вывод и ядерные оффлоады:** `sendmmsg`/`recvmmsg`, UDP GSO/GRO, TUN GSO/GRO, распределение декапсуляции по ядрам CPU (RPS), адаптивный контроллер пути (`pkg/pathctl`), userspace-клэмпинг TCP SYN MSS (`pkg/tcpmss`) и замер скорости по `TCP_INFO` (`Bytes_acked`) в скользящем окне 1 с.

## Как это работает

```mermaid
flowchart LR
  U((Users)) -->|":443"| IR["Iran server<br/>ctunnel"]
  IR ==>|"t1 · gre<br/>10.77.1.0/30"| K1["Kharej 1"]
  IR ==>|"t2 · dtls-1.3<br/>10.77.2.0/30"| K2["Kharej 2"]
  IR ==>|"t3 · rudp-fec<br/>10.77.3.0/30"| K3["Kharej 3"]
```

1. На иранском сервере вы создаёте туннель и получаете однострочную ссылку `ctunnel://`.
2. Вставляете ссылку на зарубежном (kharej) сервере. Адреса, порты, ключи и MTU на обеих сторонах совпадают автоматически.
3. Пользователи подключаются к порту иранского сервера, а C-Tunnel передаёт трафик через туннель на зарубежный сервер.

Каждый туннель получает свою подсеть `10.77.N.0/30`, свой сетевой интерфейс и свой UDP-порт, поэтому можно подключить сколько угодно зарубежных серверов без конфликтов.

## Требования

- Linux с systemd: Ubuntu 20.04+, Debian 11+ или аналогичный
- `amd64`, `arm64` или `armv7` (32-битный ARM)
- Права root
- Публичный IP на каждом сервере и разрешённый у провайдера протокол или UDP-порт туннеля

`install.sh` сам установит `iproute2`, `iptables` и `curl`, если их нет. Для WireGuard дополнительно нужен `wireguard-tools`.

## Установка

Одна команда на **обоих** серверах:

```bash
sudo bash -c "$(curl -sL https://raw.githubusercontent.com/CIAUB/C-Tunnel/main/install.sh)"
```

Установщик всегда ставит последний [релиз](https://github.com/CIAUB/C-Tunnel/releases/latest).
Он скачивает бинарники для архитектуры сервера, скрипт ядра и юниты systemd, сверяет каждый файл
с `SHA256SUMS` релиза и устанавливает только при совпадении всех хэшей. Повреждённый или изменённый
файл прерывает установку, и в системе ничего не меняется.

```bash
sudo ctunnel
```

Для обновления выберите **Update** в меню или выполните команду установки ещё раз. Работающие
туннели сохраняются. Без версии устанавливается последний стабильный релиз GitHub; черновики и предварительные релизы исключаются. Для конкретной версии:

```bash
sudo bash -c "$(curl -sL https://raw.githubusercontent.com/CIAUB/C-Tunnel/main/install.sh)" v0.2.1
```

Также поддерживаются `bash install.sh v0.2.1` и `CTUNNEL_VERSION=v0.2.1`. Явный аргумент версии имеет приоритет над переменной окружения.

## Быстрый старт

**1. Иранский сервер**, по одному разу для каждого зарубежного сервера:

```text
sudo ctunnel  →  1) Setup Iran
  Method              gre        (dtls-1.3, если GRE блокируется)
  Remote server IP    203.0.113.10
  Forward ports       443
```

Меню выведет ссылку настройки:

```text
ctunnel://eyJuYW1lIjoidDEiLCJyb2xlIjoia2hhcmVqIiwibWV0aG9kIjoiZ3JlIi...
```

**2. Зарубежный сервер:**

```text
sudo ctunnel  →  2) Setup Kharej  →  вставьте ссылку
```

или одной командой:

```bash
sudo ctunnel apply-link 'ctunnel://...'
```

**3. Проверка:**

```bash
sudo ctunnel status
```

```text
 NAME      METHOD       ROLE   REMOTE           TUNNEL IP      PORT   STATE    RX / TX
 t1        gre          iran   203.0.113.10     10.77.1.1      0      up       1.2 GiB / 310.4 MiB
 t2        dtls-1.3     iran   203.0.113.11     10.77.2.1      24002  up       842.7 MiB / 95.1 MiB
```

Чтобы добавить ещё один зарубежный сервер, повторите шаг 1 с его IP. Новый туннель получит `10.77.2.0/30`, следующий свободный порт и собственные пробрасываемые порты.

На время теста на иранском сервере должны быть открыты UDP 7712, TCP 7711 и IP-протоколы 4, 41, 47, 50, 97 и 115.

### Режим REVERSE

В режиме REVERSE подключается зарубежный сервер, а иранский только слушает, поэтому Иран никогда не открывает соединение на зарубежный IP.

| Уровень | Как идёт трафик | Лучше всего для |
|---|---|---|
| UDP-Crypt (`rev+dtls-1.3`, `rev+quic-v1`…) | kharej шлёт UDP в Иран, те же пакеты, что в DIRECT | каналы с потерями или большой задержкой |
| WireGuard (`rev+wireguard`) | kharej — клиент WireGuard | MikroTik и обычные клиенты |
| Ядро L3/L2 (`frp+gre`, `frp+vxlan`…) | внутри 8 параллельных TCP-потоков в виде TLS-записей | чистые каналы, где проходит только TCP |

Каждое внутреннее соединение остаётся в одном потоке и не перемешивается, у каждого потока своя очередь. В нашем тесте скорость TCP-несущей выросла примерно вдвое по сравнению с 0.1.5 (около 390 → 690 Мбит/с на канале 800 Мбит/с). Тест соединения проверяет и все варианты REVERSE: строка `rev+` для каждого UDP-метода и отдельные строки `frp+METHOD` с новыми TCP-потоками, проверкой payload и независимым измерением скорости. Это проверка формы трафика несущей, а не интеграционный тест туннеля ядра. В Best Settings указан самый быстрый вариант REVERSE.

## Веб-панель

Откройте `sudo ctunnel` → **4) Web Panel** → **Start** и используйте полный URL из меню. При первом запуске используется HTTP с сохранённым случайным путём:

```text
http://<server-ip>:6969/panel-<random-id>/
```

Код входа показан в том же меню. Пять неверных попыток блокируют IP на пять минут. Смена кода завершает существующие сеансы.

В **Settings → Panel settings** можно изменить путь и домен. Укажите пути к действительным `fullchain.pem` и соответствующему `privkey.pem`, либо загрузите их через HTTPS/loopback. Проверенная пара автоматически включает HTTPS с плавным перезапуском слушателя. DNS должен указывать на сервер; порт панели должен быть доступен. После изменения адреса или транспорта войдите снова.

**Link test** принимает ссылку `ctunnel-test://` второго сервера и измеряет методы отдельно. **Deploy Best Tunnel** создаёт локальную сторону по лучшему успешному результату и возвращает ссылку настройки другой стороны. Тесты формы пакетов не заменяют проверку реального туннеля ядра.

Скриншоты сделаны в Chromium из реального интерфейса с демонстрационными данными: [мобильный вид](docs/panel-mobile.png), [настройки](docs/panel-settings.png), [изменения и обновление](CHANGELOG.md).

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| Состояние `failed` | Посмотрите журнал выше. Обычно не хватает модуля ядра (`modprobe ip_gre`) или протокол заблокирован провайдером. |
| Состояние `up`, но трафика нет | Другая сторона не настроена или файрвол отбрасывает туннель. Откройте UDP-порт для UDP-Crypt и WireGuard или протокол 47 для GRE. |
| UDP-Crypt отбрасывает пакеты после перезапуска | Часы обоих серверов должны быть примерно верными (NTP), так как номера пакетов начинаются от текущего времени. |
| Проброшенный порт не отвечает | Служба на зарубежном сервере должна слушать `0.0.0.0` или IP туннеля. |
| `sit` / `ip6ip6` не пробрасывают порты | Они передают только IPv6. Используйте `6to4`. |

## Сборка из исходников

```bash
git clone https://github.com/CIAUB/C-Tunnel.git
cd C-Tunnel
go test ./...
sudo bash install.sh                  # сборка и установка из этой папки
bash scripts/build-release.sh 0.1.0   # файлы релиза и SHA256SUMS в dist/
```

**Публикация релиза:** укажите версию в `pkg/version/version.go`, сделайте коммит и отправьте тег
(`git tag v0.1.1 && git push origin v0.1.1`). GitHub Actions запустит тесты, соберёт все файлы вместе с
`SHA256SUMS` и опубликует релиз; команда установки сразу начнёт его использовать.
Устройство проекта описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

> Методы UDP-Crypt делают пакеты похожими на DTLS, QUIC, RTP и другие протоколы для простых фильтров, но не являются полными реализациями этих протоколов.
